1. Fundamentos Java

Perguntas rápidas — responda em 30–60 segundos cada.

1

Qual a diferença entre == e .equals()?

Gabarito == compara referência (se é o mesmo objeto na memória) para tipos por referência. .equals() compara o conteúdo/valor, quando a classe sobrescreve o método (ex.: String). Para primitivos, == compara o valor.
2

Explique List, Set e Map com um exemplo de uso.

Gabarito List: ordem + permite duplicados (lista de pedidos). Set: sem duplicados (conjunto de e-mails únicos). Map: chave → valor (id do usuário → usuário).
3

O que são checked e unchecked exceptions?

Gabarito Checked: o compilador obriga tratar ou declarar (ex.: IOException). Unchecked: RuntimeException e subclasses (ex.: NullPointerException, IllegalArgumentException) — não são obrigatórias no compile-time.
4

O que é injeção de dependência e por que o Spring usa isso?

Gabarito Em vez da classe criar suas dependências (new), ela recebe pronta (construtor). Isso facilita testes, troca de implementação e deixa o código mais desacoplado. O Spring gerencia o ciclo de vida dos beans e injeta as dependências.

2. Spring Boot & API REST

Núcleo da vaga. Priorize esta seção.

5

O que o Spring Boot resolve em relação ao Spring “puro”?

Gabarito Reduz configuração manual com auto-configuration, starters (web, data-jpa), servidor embutido (Tomcat) e convenções prontas. Você sobe uma API mais rápido e com menos XML/config boilerplate.
6

Explique a responsabilidade de Controller, Service e Repository.

Gabarito Controller: recebe HTTP, valida entrada básica, devolve response. Service: regra de negócio e orquestração. Repository: acesso a dados (JPA/banco). Separar isso deixa o código limpo e testável.
7

Diferença entre @RestController e @Controller?

Gabarito @RestController = @Controller + @ResponseBody. Ideal para API JSON. @Controller costuma retornar views (HTML/templates), a menos que use @ResponseBody no método.
8

Quando usar GET, POST, PUT, PATCH e DELETE?

Gabarito GET: buscar (não altera estado). POST: criar. PUT: substituir recurso inteiro. PATCH: atualizar parcial. DELETE: remover. GET deve ser idempotente/seguro; PUT/DELETE idempotentes na prática REST.
9

Cite status HTTP comuns e quando usar cada um.

Gabarito 200 OK, 201 Created, 204 No Content, 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 409 Conflict, 500 Internal Server Error.
10

O que é DTO e por que não expor a Entity direto?

Gabarito DTO é um objeto de transferência para entrada/saída da API. Evita vazar campos internos, reduz acoplamento com o banco, facilita validação e evita problemas de serialização/lazy loading do JPA.
11

Como você trata erros de forma padronizada numa API?

Gabarito Com @ControllerAdvice + @ExceptionHandler, devolvendo um JSON padrão (mensagem, código, timestamp, campos inválidos). Também validação com @Valid + Bean Validation (@NotBlank, @NotNull).
12

O que vai no application.properties/application.yml?

Gabarito Porta do servidor, configuração do banco (url, user, password), dialeto JPA, ddl-auto, profiles (dev/prod), logs, etc. Segredos não devem ir commitados — usar env vars/secrets.

3. JPA, banco e SQL

Muito comum em entrevista júnior backend.

13

O que é JPA e o que é Hibernate nesse contexto?

Gabarito JPA é a especificação (API) de persistência. Hibernate é uma implementação dessa especificação (ORM). No Spring Data JPA, geralmente usamos Hibernate por baixo.
14

Diferença entre @Entity, @Id e @GeneratedValue?

Gabarito @Entity: classe mapeada para tabela. @Id: chave primária. @GeneratedValue: estratégia de geração do id (IDENTITY, SEQUENCE, etc.).
15

Explique relacionamento @OneToMany / @ManyToOne com exemplo.

Gabarito Ex.: Pedido tem muitos Itens (@OneToMany); cada Item pertence a um Pedido (@ManyToOne). O lado Many costuma ter a FK. Cuidado com cascata e fetch lazy/eager.
16

O que é Lazy Loading e qual problema clássico ele causa na API?

Gabarito Lazy carrega o relacionamento só quando acessado. Fora da transação pode dar LazyInitializationException. Por isso usamos DTO, join fetch, @EntityGraph ou mapeamento cuidadoso — e evitamos serializar entity com proxy lazy.
17

Escreva um SQL: buscar usuários ativos ordenados por nome.

Gabarito SELECT * FROM usuarios WHERE ativo = true ORDER BY nome ASC; (sintaxe pode variar: 1/0 no Oracle/MySQL antigo, etc.)
18

Diferença entre INNER JOIN e LEFT JOIN?

Gabarito INNER JOIN: só registros com correspondência nas duas tabelas. LEFT JOIN: todos da esquerda + correspondências da direita (ou null se não houver).

4. Mini cenário técnico (como no projeto)

Treine pensar em voz alta — é o que o time avalia.

19

Como você modelaria um CRUD de Produto (campos, endpoints, camadas)?

Roteiro bom Entity Produto (id, nome, preco, ativo). DTOs de create/update/response. Endpoints: POST/GET/GET{id}/PUT/PATCH/DELETE em /produtos. Repository JpaRepository, Service com regras (preço > 0, nome obrigatório), Controller com ResponseEntity e status corretos. Mencionar validação e tratamento de “não encontrado”.
20

Um endpoint está lento. O que você investigaria primeiro?

Roteiro bom Reproduzir, olhar logs, medir tempo, checar query N+1, índices no banco, volume de dados, serialização pesada, chamadas externas. Para júnior: mostrar método (não chutar solução mágica).
21

Como você evita N+1 queries no JPA?

Gabarito Detectar (logs SQL), usar join fetch / entity graph, projetar só campos necessários (DTO/interface projection), evitar EAGER em tudo, paginar listas grandes.

22

Explique o fluxo: branch → commit → push → pull request.

Gabarito Crio branch a partir de main, desenvolvo, faço commits claros, push da branch, abro PR para revisão. Após aprovação/CI, merge. Em consultoria isso é rotina.
23

O que você testa numa API júnior (pelo menos o básico)?

Gabarito Testes unitários do service (regras), testes de controller com MockMvc, validar status HTTP e JSON. Se possível, teste de integração do repository. Mencionar JUnit 5 e Mockito já conta ponto.
24

Diferença entre autenticação e autorização?

Gabarito Autenticação: quem é você (login/token). Autorização: o que você pode fazer (roles/permissões). Em Spring, isso aparece no Spring Security.
